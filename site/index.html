Why wait Evals Install FAQ

Agents install fresh versions within hours of release. So do worms.

package-guidance is an agent skill, a CLI and a Claude Code hook. Before your agent adds a dependency, it checks the live registry, pins the newest settled version (7+ days old, no known advisories), refuses names that don’t exist, and points to the migration when a package is dead.

$ npx skills add harshpreet931/package-guidance

On Claude Code, the plugin also adds an install hook. Works with Cursor, Codex and anything that reads AGENTS.md.

Same request. One agent checks first.

Asked to add an HTTP client, date handling and Sass, an agent types what it remembers. With package-guidance it asks the registry, swaps the dead packages, and pins what has settled.

Every $ command and its output is a real capture from 2026-11-16, trimmed where marked. “agent ›” lines are narration. The unguided install ran with --ignore-scripts, so node-sass skipped its native build.

Agents guess. The registry doesn’t.

Latest isn’t safe. Settled is.

Compromised releases are published as the latest version and usually get pulled within hours. An agent that installs @latest the minute it ships is exactly who those hours are for. A 7-day cooldown skips the whole window.

pnpm, npm, yarn, bun and uv can enforce a release-age cooldown themselves. package-guidance harden sets it up for your repo, and the hook respects it.

Seven checks before any install

The skill gives your agent one procedure to run before it adds a dependency. The CLI does the lookups against live registry data, so the agent never relies on memory.

7 days, then pin
  1. 1

    Need it?

    Prefer the platform: fetch, crypto.randomUUID(), structuredClone, node --env-file, zoneinfo. Fewer dependencies, fewer attack surfaces.

    replace
  2. 2

    Right package?

    Not deprecated, sunset or superseded. Curated entries plus the e18e module-replacements dataset and the registry’s own flag.

    deprecatedoutdated
  3. 3

    Real package?

    A registry 404 means a hallucination. Never install it, and never guess a similar name.

    not-foundunproven
  4. 4

    Settled version

    The newest release at least 7 days old. A newer one only if it fixes an advisory on the older one.

    youngok
  5. 5

    No known advisories

    The pinned version is checked against OSV.dev, which includes malicious-package reports.

    vulnerablemalicious
  6. 6

    Respect project policy

    If the repo configures a release-age cooldown, keep it. Never lower, remove or bypass it to make an install succeed.

  7. 7

    Pin exactly

    Install pkg@1.2.3 or pkg==1.2.3 and commit the lockfile.

    install

Install for every agent

It is one skill file. Use whichever loader your agent already has.

Installs the skill into any agent the skills CLI supports: Claude Code, Codex, Cursor, Copilot, Gemini CLI and more.

$ npx skills add harshpreet931/package-guidance

The plugin adds the skill and a PreToolUse hook on Bash. The hook denies hallucinated, malicious, deprecated and known-vulnerable installs, and unpinned installs whose latest release is inside the cooldown. It never approves anything, fails open on network errors, and costs about 25 ms on commands that install nothing.

› /plugin marketplace add harshpreet931/package-guidance › /plugin install package-guidance@package-guidance

Set PACKAGE_GUIDANCE_HOOK=warn to never deny, or off to disable the hook.

The same skills CLI, pointed at one agent.

$ npx skills add harshpreet931/package-guidance --agent cursor $ npx skills add harshpreet931/package-guidance --agent codex

Copy copies the Cursor line. Or paste the AGENTS.md snippet into .cursor/rules.

No loader? Paste this into AGENTS.md, CLAUDE.md or .cursor/rules.

## Dependencies Before adding or upgrading any npm or PyPI package, run `npx -y package-guidance@0.1.0 check <pkg>... --json` (add `--pypi` for Python) and install the returned `install` command verbatim. Never install `not-found`, `deprecated`, `malicious` or unfixed `vulnerable` packages, never guess a similar name, and never lower a configured release-age cooldown.

The snippet pins package-guidance@0.1.0 on purpose. We don’t tell agents to run @latest either.

The CLI

Zero runtime dependencies. The agent calls it, and so can you. It exits with 1 when anything is blocked, so scan works in CI.

check <pkg[@range]>…
A verdict and a pinned install line for each package. Add --pypi for Python.
scan [dir]
Audits package.json, pyproject.toml or requirements.txt.
guide [id | query]
Curated migrations: CRA to Vite, Tailwind v4, ESLint flat config, moment to date-fns.
harden [dir] [--write]
Sets a release-age cooldown in your package manager’s own config: npm, pnpm, Yarn, Bun or uv.
hook
The Claude Code PreToolUse handler (stdin JSON).
Options
--cooldown <days> --json --cwd <dir> --no-cache -v
okInstall the pinned version.
cautionInstallable, with a known risk worth reading.
outdatedThe requested range is on an old major.
replaceUse one of the alternatives, native APIs first.
deprecatedDeprecated on the registry or sunset by its maintainers.
vulnerableHigh/critical advisories; fixedIn is the settled fix.
maliciousOSV reports this release as malware.
not-foundThe package or version doesn’t exist. Almost always a hallucination.
young · unprovenBrand-new or barely downloaded. Confirm it’s the real one.

Questions

Something wrong or missing? Open an issue.

Isn’t this what Socket, Snyk and Dependabot do?

They are excellent, and they run after the choice: in CI, on a PR, or on a package the agent already picked. package-guidance runs at the moment of choice, inside the agent, and tells it what to pick instead. Use both.

Doesn’t “latest” mean “safest”?

No. @latest is exactly where compromised releases appear first, and they are usually pulled within hours. The hijacked chalk and debug releases were live for about two hours. Waiting 7 days skips that window; the only exception is a newer release that fixes an advisory on the version you would otherwise pin.

Do you follow your own advice?

Yes. The skill and the hook run an exact pinned version of this tool (package-guidance@0.1.0), never @latest. Our GitHub Actions are pinned to commit SHAs and respect the cooldown too.

Does it send telemetry?

No. The only network calls are public lookups: deps.dev, the npm and PyPI registries, OSV.dev and npm download counts. No API keys. Responses are cached for an hour in ~/.cache/package-guidance.

Will it slow my agent down?

A check takes about a second cold and is near-instant from cache. The hook does nothing unless a command installs packages, and costs about 25 ms when it doesn’t.

What if the registry is down, or I use a private one?

The hook fails open: a network error or timeout never blocks you. It never denies a 404 on a private registry.

Python?

Yes. Add --pypi: npx package-guidance check --pypi "pydantic<2" fastapi. The hook understands pip, uv and poetry.
